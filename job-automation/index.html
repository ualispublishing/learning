The runner reuses one employer tab and never marks an application submitted merely because a tab opened or closed. Reloading or reopening a fresh seeded link preserves completed progress for matching URLs.

Pages-only boundary

GitHub Pages cannot directly autofill another company's tab.
Browser same-origin security prevents this static page from reading or modifying employer forms, triggering their file inputs, or observing their submission result.
Automated here:
encrypted queue loading, duplicate removal, priority ordering, one-tab sequencing, local progress, blocker categorization, stale-posting tracking, retry/undo, and progress export/import.
Default ordering:
high-fit roles are balanced against expected ATS friction, so strong employer-native applications are generally attempted before login/CAPTCHA-heavy routes.

Browser-native saved-address/password autofill can still work on employer pages. Human verification, legal attestations, subjective answers, résumé upload, and final application confirmation remain on the employer page.
