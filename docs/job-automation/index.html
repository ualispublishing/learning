The runner reuses one employer tab. It never marks an application submitted just because a tab was opened or closed.

Pages-only boundary

Autofill across employer sites is not technically available from GitHub Pages alone.
A normal web page is prevented by browser same-origin security from reading or modifying fields in another company’s tab. GitHub Pages also cannot run a server-side browser or upload a résumé into another origin.
What this mode does automate:
keeps the encrypted ready queue, opens jobs sequentially, reuses one application tab, tracks submitted/blocked/skipped state locally, and advances immediately after your result choice.

CAPTCHA and other human checks remain on the employer page. Browser-native saved-address/password autofill can still work normally, but this Pages tab cannot trigger or control it.
